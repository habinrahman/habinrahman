## Where I am

I've spent the last stretch building backend platforms that other systems and people depend on in production — enrollment orchestration, campaign automation, verification infrastructure. That work forced a specific discipline: explicit state, idempotent operations, and observability that isn't optional.

I'm now pointing that discipline at **agentic AI** — systems where an LLM doesn't just answer, it plans, calls tools, and carries state across steps. I'm not new to AI (RAG, embeddings, and LLM-integrated services are already in my project history below), but I'm early and honest about it on the *agentic* side specifically: **LangGraph, MCP, and AI evaluation are active learning, not claimed expertise.**

If you're hiring for someone who can make an agent reliable, not just make it demo well — that's the gap I'm closing.

## How I build

- **Reliability is a feature**, not a phase that happens after launch.
- **Idempotency over optimism** — every operation assumes it might run twice.
- **State transitions should be explicit** — implicit state is where production incidents live.
- **Automation should be observable** — if you can't see it working, you can't trust it.
- **Simplicity scales; unnecessary complexity doesn't.**

These aren't slogans — they're the same principles from the systems above, applied now to agent design: an agent's state machine needs the same rigor as a backend's.
